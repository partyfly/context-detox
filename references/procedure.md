# 清毒工序(完整版)

## 一、审计查表(七件套 × 四病理)

对本次任务**读过或写过**的每一件持久物,按其所属件查对应病理。没触过的件跳过——清毒本身也要遵守"相关"标准。

| 审计面(件) | 对应持久物 | 中毒(错断言被当真) | 分心(厚历史压过新判断) | 混淆(无关在场带偏) | 冲突(权威打架信错) |
|---|---|---|---|---|---|
| 指令件 | 系统提示、CLAUDE.md、技能、风格包、规则文件 | 规则里有无凭印象写的"事实"(版本号、路径、行为描述) | 规则条数是否还在涨、有无一条链能替代十条禁令 | 有无为旧项目写的规则仍全局生效 | 新裁定与正文矛盾处是否已改正文 |
| 输入件 | 用户本次的裁定、给的参照 | 裁定转写时有无走样(对照原话) | — | — | 与既有规则冲突时,优先级链写了吗 |
| 检索件 | 记忆召回、RAG/材料文档、被引用的旧文件 | 材料文档里的压缩产物(如"干货提取")被当唯一事实源了吗 | 召回条目过多是否掩盖了关键两条 | 被点名"不要参照"的东西有范围注记吗 | 两份材料数据不一致处标注了信谁吗 |
| 工具件 | 工具说明、脚本注释、用法文档 | 注释描述与当前实现还一致吗(重读代码) | — | 已废弃工具的说明还在被加载吗 | 两份用法文档不一致时留哪份 |
| 短期笔记 | 会话摘要、压缩产物、交接说明 | 摘要里的工程断言逐条标来源了吗(重读过原文 vs 转述) | 摘要是否复读了整段历史而非只留裁定 | 摘要里带了与后续无关的过程细节吗 | 摘要与源文件矛盾时以谁为准写明了吗 |
| 长期记忆 | memory 文件与索引 | 每条裁定有日期+适用范围吗;被推翻的删了吗 | 同文件"追加"超两层了吗(触发合并重写) | description 触发面是否过宽(无关任务也会召回) | 两条记忆互相矛盾吗(留新删旧并注明) |
| 输出格式件 | 产出模板、命名约定、交付格式 | 模板示例里的数据是真的吗 | — | 上个项目的模板混进本项目了吗 | 两套命名并存时定了正字吗 |

## 二、工件一:审计表(必填)

每行一件持久物:`文件路径 | 所属件 | 本次读/写 | 发现(无/嫌疑描述) | 病理定性`。
机械预扫(scan.py)的输出并入此表,标注"机器嫌疑,待人工判"。

## 三、工件二:清理清单(必填)

每行一个问题:`问题 | 病理 | 处方动作(写出去/挑选/压缩/隔离 之一,具体到操作) | 改哪个文件 | 需确认?`

处方动作对照:
- **写出去**:把窗口内孤本裁定落成持久物,带日期+适用范围;摘要断言改写为"结论+来源指针"。
- **挑选**:收窄 memory description 的触发面;把常驻加载改为按需引用;给"不要参照"的对象写范围注记。
- **压缩**:分层追加的文件合并重写——当前有效裁定置顶,历史压成一行;超期的"待验证"处理掉。
- **隔离**:给下一个同类任务开会话拆分方案(按工序,各带最小上下文,只回传结论);跨项目内容拆到各自文件。

## 四、边界:什么不许清

1. **不删还在承重的历史**:一条旧记录若仍被其他文件 [[引用]] 或是唯一出处,只能压缩不能删。
2. **不清对话,只清持久物**:对话窗口的混乱由新会话解决,不值得花动作。
3. **不越权改共享物**:多人共用的规则/文档,清理单标出问题即可,改动交所有者。
4. **一次只清本次触过的**:全库大扫除是另一件事(定期任务),收工清毒只看本次读写面——否则清毒本身变成"分心"。

## 五、验收(四标准四问)

对每件改过的持久物:相关(每条都为未来任务服务?)/结构(裁定与历史分得清?)/时机(按需加载还是常驻?)/压缩(还能更短而不失真?)。任一问不过,回到清理单补一条。

## 六、汇报格式

`改了:<文件:动作>… / 待验证:<断言+日期>… / 未动:<对象+原因>…`——三段都要有,空也要写"无"。
